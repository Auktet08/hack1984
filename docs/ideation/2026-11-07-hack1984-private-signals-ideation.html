Ideation: HACK1984 Track 1, Private Signals

Date: 2026-11-07 Topic: hack1984-private-signals Focus: is this track worth pursuing, and what would win it Mode: elsewhere-software (evaluating a hackathon data package in this folder)
Verdict

Go, if the event's prize and time justify roughly 1–2 days of work. The track is unusually cheap to score well in. Rules taken straight from the labeling guide, with no model at all, score 0.731 composite on the 60 dev items. Adding title regexes fitted to dev lifts that to 0.844. Your 4 GB laptop GPU is enough to build and run it, and the PubMed setup step works (0 hash mismatches on dev and test).

The catch: because a careful rules system already gets most of the way, many teams will likely cluster near the top. Dev is too small (±0.055 at 95%) to tell entries apart reliably. So the edge probably comes from the judged criteria: usefulness, privacy and cost per 100 items. That is a reasoned guess. Nothing public exists about prizes, judging weights, timeline or the organisers' hardware.

Topic Context

  • Task. For each item about Tagrisso (A) or Rybrevant/Lazcluze (B), output: signal type (9 classes), actionable yes/no, and five aspects. Each aspect is null or has polarity −2..+2, a speaker (7 classes) and a verbatim span. The model must run self-hosted and offline. Final scoring runs on the organisers' hardware with the network off.
  • Data. 60 dev items, of which only 15 were human-reviewed; the other 45 were drafted by a frontier model, then the reviewers' rulings were applied. 240 test items, 1,733 unlabeled.
  • Test sources. PubMed 104, ctgov 40, fda_event 37, news 30, press release 18, fda_label 10, fda_notice 1.
  • Dev label distribution.
    • Signal: efficacy 21, safety 16, trial_update 10, none 7, regulatory 2. Four classes have a single example each.
    • Actionable: 12/60 yes.
    • Aspects: 23/60 items have none. Efficacy 22, safety 22, evidence_quality 8, convenience 3, access_cost 1.
  • Scorer. The composite is the plain mean of 7 parts: signal macro-F1, actionable F1, aspect F1, polarity QWK, speaker accuracy, span token-F1 and citation validity. Four of the seven (QWK, speaker, span, citation) are computed only over matched or predicted aspects.
  • Speaker is fixed by source for every non-fda_event aspect (46/46 on dev). For fda_event it follows the reporter field.
  • PubMed fetch verified: 26/26 dev and 104/104 test abstracts match their hashes, and all 31 PubMed gold spans are verbatim. 1 of 896 unlabeled abstracts has changed since the freeze.
  • Your hardware: RTX 3050 Ti, 4 GB VRAM, 23 GB RAM, 16 threads. A 3–4B instruct model at Q4 fits on the GPU. A 7–8B model at Q4 runs with CPU offload; it is slow but fine for about 150 model-routed items.
  • Outside sources: nothing public about HACK1984, Within3's judging or prizes. Most model and tooling claims from web research could not be checked against primary sources.

1. Rules-first router, guide rulings as hard overrides

I1Deterministic layerConf 85%Complexity Low
Description
Route by source before any model sees an item:
  • ctgov: trial_update, actionable no, no aspects unless the stop reason says futility or toxicity.
  • fda_event: safety, safety −1, span = the reaction words, speaker from the reporter field. A small lookup table handles the special reactions (off-label use → null; disease progression → efficacy −1; can't afford → access_cost −1).
  • fda_label / fda_notice: map by section name.
A model only sees PubMed, news and press items, and its output then passes through the same code: the speaker comes from the source table, and rulings 1–10 override what the model said (for example "well tolerated" → safety +1, an earnings release → competitor_move with no aspects).
Basis
direct: Guide-only rules score 0.731 composite on dev with no model; the verifier re-ran this. 88/240 test items are ctgov, fda_event or fda_label/notice. The source-to-speaker table matches 46/46 non-fda_event gold aspects. Dev ctgov actionable is 10/10 "no".
Rationale
Over a third of the test set becomes zero-cost and close to deterministic. Overrides remove whole kinds of model error, so a 3–4B model can compete with a much larger one.
Downsides
There is no dev gold for fda_notice or for ctgov stops, so those rules rest on the guide alone. The guide says new phase 3 registrations are "usually" actionable, but dev disagrees; keep ctgov actionable at "no".

2. Optimise against the scorer's own mechanics

I2Metric mechanicsConf 80%Complexity Low
Description
Four guards, all tuned against the composite itself:
  1. QWK cliff. Make sure the matched polarities are never all identical. A rules-only system's matched aspects are all fda_event −1. If one gold label is different, QWK falls from 1.0 to 0. A few confident positive aspects (PubMed cue words, press-release efficacy) remove that risk.
  2. Precision over recall. Set the aspect-emit threshold on the composite, not on aspect F1. A missed aspect costs only one of the seven parts; a wrong one can hurt up to four.
  3. Never empty. Never submit with zero aspects.
  4. Rare classes. Give a best guess for rare signal classes that are probably in test (guideline, expert_opinion, access_pricing).
Basis
direct: The verifier reproduced each of these.
  • score.py returns QWK 1.0 when the expected-agreement term is 0.
  • On dev, one deviant gold polarity drops the composite from 0.844 to 0.701. With 11 cue-word PubMed aspects added, it holds at 0.860.
  • Zero aspects scores 0.167.
  • Macro-F1 averages only the classes present in gold.
Rationale
These are the largest swings in the whole system, and each one is a few lines of code. The QWK cliff is a 0.14 tail risk that sits on a mostly unreviewed, model-drafted gold set.
Downsides
A guess at a rare class costs a true positive in a big class when it's wrong; only do it where the cues are strong. Dev is too small to tune thresholds finely (see idea 5).

3. Extractive spans: the model points, code quotes

I3Model layerConf 75%Complexity Low–Med
Description
The span pipeline:
  1. Strip the navigation boilerplate from press releases.
  2. Split each text into numbered sentences, never across a "…".
  3. Have the model return an aspect, a polarity and a sentence number, not free text.
  4. Code trims the sentence to the clause around the cue word, about 6–10 tokens.
  5. Snap any free-text answer to an exact substring, or drop it.
Basis
direct: Citation validity is a case-sensitive in check, so an invented quote scores zero, and span F1 is a lowercase bag-of-words F1 (score.py). The first crude cue-word pass cut words in half and dropped span F1 from 0.91 to 0.72; trimming to word and clause boundaries brought it back to 0.82. Press releases have a median of about 8.4k characters and start with site navigation text.
Rationale
Citation validity is guaranteed at 1.0, the model writes fewer output tokens (which helps cost per 100 items), and span F1 stops depending on how well a small model copies text.
Downsides
A clause trimmer needs some hand-tuning. Sentence splitting on abstracts with odd punctuation can misfire.

4. Imitate the drafter with a small offline model

I4Model layerConf 65%Complexity Medium
Description
Most of the gold was written by a frontier model following the guide, so aim at its habits rather than at medical truth:
  • Put the relevant guide section and rulings verbatim in the prompt.
  • Add the closest dev examples from the same source as few-shot.
  • Keep the guide's "pick the milder level" rule.
  • Run cue-word triggers first ("retrospective" → evidence_quality −1, "well tolerated" → safety +1, "significantly improved", "immature"). The model only decides what the triggers miss and picks signal type for PubMed, news and press items.
A 3–4B instruct model at Q4 on your GPU, or 7–8B with CPU offload.
Basis
direct: 45 of 60 dev labels were frontier-drafted (README). A cue-word pass with no model added 11 PubMed aspects and lifted dev from 0.844 to 0.862, but it was fitted to dev, so treat that as an upper bound. external: In pharmacovigilance event extraction, BM25-selected few-shot examples worked best (arXiv 2402.15663).
Rationale
The model's job shrinks to about 150 items and a narrow decision. That keeps it inside your hardware and makes cost per 100 items close to zero.
Downsides
The expected gain over rules alone is modest: roughly +0.01 to +0.03 in simulation. Wrong polarities on borderline real-world studies (+2 where gold says +1) erase the gain, as the first cue-word pass showed.

5. Build an honest validation set and keep test out of it

I5Go / no-go riskConf 70%Complexity Medium
Description
Hand-label about 100 items from the unlabeled pool, chosen where rules and model disagree (news, press, PubMed reviews, protocols, case reports), and use them with dev to make decisions. Write every rule from the guide, dev and the unlabeled set only. Never read test inputs while designing rules. Treat the generator's exploratory test predictions and test-input printouts from this session as off-limits, and rebuild rules cleanly.
Basis
direct:
  • A bootstrap 95% interval for the dev composite is about 0.754–0.864, so dev can't separate changes under about 5 points.
  • Four signal classes have one dev example each.
  • The README bans only hand-labelling test items.
  • The verifier found that an exploratory script here printed test-input titles and reaction vocabulary. It didn't look at labels, but it breaks the spirit of the rule.
Rationale
Without this, most of v2's +0.11 over v1 is probably dev overfitting, and a rules entry is exactly the kind a judge might check for test leakage.
Downsides
2–3 hours of careful labelling, and your labels will differ somewhat from the frontier drafter's.

6. Pitch the judges: a launch-team digest

I6JudgingConf 60%Complexity Medium
Description
Present the output as what a launch team would actually read:
  • A weekly board with one card per event. Group the same news across sources, for example a press release and its news repost.
  • Actionable items first, each insight linked to its verbatim quote.
  • A measured cost per 100 items (laptop time plus watts).
  • A run recorded with the network unplugged, as proof it works offline.
Basis
direct: The README says judges weigh usefulness, privacy (network off) and cost per 100 items. Dev and test contain the same events from several sources: NW-0046 and NW-0057 (ADAURA), and NW-0052 and NW-0053 (J&J Q2 2026). reasoned: If leaderboard scores cluster, these criteria decide the ranking.
Rationale
A rules-first design gives a very strong cost and privacy story: most items never touch a model. That differentiates you once scores are close.
Downsides
Demo time competes with scoring work, and the judging weights are unknown. Event grouping adds nothing to the composite.
Unknowns that could flip the verdict

The event's length and prize; the judging weights; the organisers' hardware (it decides whether a 30B-class model is an option); and whether other teams will use frontier-labelled distillation, which is allowed but costs privacy points.
